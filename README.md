# yesnoquestions

Минималистичный опрос: один вопрос и две кнопки. Закрытая админка находится по адресу `/admin`.

## Что внутри

- Next.js App Router, TypeScript, React. Серверные обработчики совместимы с Vercel Functions.
- Neon Postgres для production, подключается через Vercel Marketplace. Все запросы параметризованы; соединения идут через serverless HTTP driver.
- Для локальной разработки — настоящий встроенный Postgres (PGlite), файлы в `.data/poll`. Без сторонних сервисов и без фиктивной статистики. В production локальная база отключена.
- Статистика: уникальные браузеры, ответы, доля ответивших, распределение да/нет, активность за 7 дней, история опросов. Дни считаются по UTC.
- Изменение текста сохраняет ответы; новый опрос начинает новую статистику и сохраняет предыдущую в истории. Приостановка блокирует ответы на сервере.

## Запуск локально

Нужен Node.js 22+.

```sh
npm ci
cp .env.example .env.local
openssl rand -hex 32
npm run admin:password
```

Запишите случайную строку в `SESSION_SECRET`, задайте `ADMIN_USERNAME`, результат команды пароля — в `ADMIN_PASSWORD_HASH`. Пароль вводится скрыто, его значение не записывается в историю команд. `DATABASE_URL` оставьте пустым для локального Postgres.

```sh
npm run dev
```

Откройте `http://localhost:3000`. Начальный вопрос: «Should we say yes more often?». Меняется через админку.

Если в рабочей копии уже есть `.env.local`, не перезаписывайте её. Созданные при подготовке проекта локальные реквизиты находятся в `.data/local-admin.txt`; эти файлы исключены из Git. Не используйте их для публичного сайта.

## Деплой на Vercel

1. Загрузите проект в свой Git-репозиторий и импортируйте в Vercel. Framework preset: **Next.js**, Node.js **22.x** или новее. Build: `npm run build`. Output Directory оставьте по умолчанию.
2. Добавьте **Neon** через Vercel Marketplace → Storage, подключите базу к проекту. Интеграция создаст `DATABASE_URL`. Выберите близкие регионы для базы и Vercel Functions.
3. В Environment Variables задайте `SESSION_SECRET` (случайная строка от 32 символов), `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH` (сгенерированный командой выше). Никакие секреты не должны иметь префикс `NEXT_PUBLIC_`.
4. Примените схему **один раз до использования сайта**: локально положите строку Neon в `DATABASE_URL` в `.env.local` и выполните `npm run db:migrate`. Скрипт идемпотентен, выполняется транзакционно и не удаляет ответы. Он не запускается при сборке: preview-сборки не должны менять production-базу.
5. Выполните Deploy / Redeploy. Проверьте публичный опрос и `/admin`.
6. Для Preview используйте отдельную базу / ветку Neon и отдельные секреты. Применяйте миграцию к каждой новой базе. Не подключайте тестовые развёртывания к рабочим ответам.

При отсутствии базы или секретов production не переходит на временное хранилище. Сообщение об ошибке не раскрывает секреты. Vercel автоматически определяет конфигурацию Next.js: отдельный `vercel.json` не требуется.

Официальные инструкции: [Postgres на Vercel](https://vercel.com/docs/postgres), [интеграция Neon](https://vercel.com/integrations/neon).

## Как считается уникальность

Сервер создаёт случайный UUID, подписывает его HMAC и помещает в `HttpOnly`, `SameSite=Lax` cookie на год; в production используется `Secure`. В базе сохраняется HMAC идентификатора, сам cookie не доступен JavaScript. Просмотр учитывается после успешного запроса браузера, а не при загрузке HTML ботом.

На каждую пару «опрос + браузер» действует уникальное ограничение Postgres и для визитов, и для голосов. Даже одновременные повторные запросы сохраняют один голос. Повторная отправка возвращает сохранённый выбор. Круглая стрелка под кнопками позволяет сбросить свой ответ и выбрать заново: старый голос удаляется из статистики, а посетитель остаётся тем же. Перезагрузка восстанавливает актуальное состояние. Сброс доступен только для текущей версии активного опроса. Старый вопрос, его изменённая версия и опрос на паузе не принимают новые ответы.

**Это уникальные браузеры, а не идентифицированные люди.** Инкогнито, другое устройство, удаление или блокировка cookie ограничивают точность. Один общий браузер считается одним участником. Без входа респондентов невозможно надёжно запретить одному человеку голосовать с разных устройств. Мы сознательно не используем IP для уникальности и не собираем отпечаток устройства. Статистика описывает добровольно ответившую аудиторию, а не репрезентативную выборку населения. От автоматизированной накрутки со сменой cookie этот механизм не защищает; для публичных кампаний используйте Vercel Firewall / bot protection, а для строгого «один человек» потребуется авторизация участников.

## Защита админки

- Пароль хранится в переменной окружения в виде scrypt-хеша с солью.
- Сессия подписана, живёт 8 часов, хранится только в `HttpOnly` cookie. Смена логина/хеша пароля или `SESSION_SECRET` инвалидирует существующие сессии. Изменение `SESSION_SECRET` также сбрасывает распознавание посетителей — не меняйте его без необходимости.
- Все серверные маршруты админки проверяют сессию. Статистика и API-ответы не кешируются.
- Изменяющие запросы проверяют Origin. Есть защита от встраивания страницы и MIME sniffing.
- Ограничение входа хранится в Postgres и работает между экземплярами Vercel: 10 попыток за 15 минут на HMAC IP, максимум 100 попыток за окно на всё приложение. Сырой IP не хранится. Защитные записи не входят в статистику опроса.

## Проверка

```sh
npm test
npm run typecheck
npm run build
```

Тесты используют отдельный Postgres в памяти: дедупликация параллельных голосов, сохранение первого выбора, сессии, права доступа, Origin, пауза, устаревшие вопросы, история и ограничение входа. Рабочие данные не затрагиваются.
